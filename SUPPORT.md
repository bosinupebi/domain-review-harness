# Support

For reproducible defects, open a bug issue with the harness commit/version, operating system, command (sanitized), expected result, actual result, and a synthetic reproduction. For a feature, explain the company workflow it supports and how success would be measured.

For usage questions, read docs/usage.md and docs/troubleshooting.md, then open a question issue. Support is community-driven and best effort; there is no service-level agreement. Repository access is required while the project is private.

Security-sensitive reports follow SECURITY.md. Never attach complete company run directories to issues.
